Design & setup

Why the system is shaped this way, and how to run it on your own Supabase project.

Analysis

Catalog management

One record per SKU with a lifecycle: draft, ready, published, archived. A product reaches "ready" only at 100% completeness, enforced in the database so no client can bypass it.

Attribute handling

Attributes are defined centrally (type, allowed values, unit), attached to categories and stored per product as validated JSON. Adding an attribute needs no schema change.

Data synchronization

Pushes send only products whose content hash changed. Stock flows back. Edits made in the store to PIM-owned fields raise a conflict for a person to resolve.

How it fits together

Data model (Supabase)

  • products: core columns plus attributes jsonb, images jsonb, completeness and content_hash, both set by a trigger.
  • attribute_definitions and category_attributes: what exists, and which categories use it (required or optional).
  • categories: a tree with an optional wc_category_id.
  • wc_product_map: the link to each WooCommerce product, the hash last pushed, a snapshot of store values and any open conflict.
  • sync_jobs, sync_log, product_history: what ran, what happened to each product, and who changed what.
  • Roles in profiles: admin (everything), editor (products), viewer (read only). Sync tables are written only by edge functions.

Run it on your Supabase project

  1. Create a project at supabase.com and install the Supabase CLI.
  2. From the project folder: supabase link --project-ref YOUR_REF, then supabase db push to apply the migrations. Optionally run supabase/seed.sql in the SQL editor for sample data.
  3. Create a WooCommerce REST key (Read/Write) and store the secrets: 
    supabase secrets set WC_URL=https://shop.example.com WC_KEY=ck_xxx WC_SECRET=cs_xxx \
  WC_WEBHOOK_SECRET=long-random-string CRON_SECRET=another-random-string
  4. Deploy the functions: supabase functions deploy woo-push woo-pull woo-webhook
  5. In WooCommerce add a webhook for Product created, Product updated and Product deleted pointing to https://YOUR_REF.supabase.co/functions/v1/woo-webhook with the same secret.
  6. In Supabase Authentication add your users. The first user becomes admin; later users are viewers until an admin changes their role.
  7. Paste your project URL and anon key into PIM_CONFIG in web/index.html and host the file anywhere static (or open it with npx serve web).

WooCommerce credentials live only in Supabase secrets. They never reach the browser or the database.
